## Objective

Make Baru Budget reachable from the internet, including mobile, with e-mail and password login, persistent session, protected routes and the v0.1 schema applied to the hosted Supabase project. Architecture reference: `docs/ARCHITECTURE_ANALYSIS_V0.2.md`.

- Cloudflare Pages project with automatic deploy from `main`; `_headers`, `robots.txt`.

## Technical Behavior

- The session is persisted by supabase-js (localStorage) and refreshed automatically. `AuthService.ready` resolves after the initial `getSession()`; guards await it, so a page refresh on a protected route keeps the user signed in instead of bouncing to the login page.
- `authGuard` redirects anonymous users to `/login?returnUrl=<path>`; after signing in the page navigates to the return URL only when it is a same-origin absolute path, otherwise to `/dashboard`.
- `CurrentProfileService` loads the profile whenever the authenticated user changes and clears it on logout. The header shows the e-mail while the profile is loading.
- Sign-in errors are mapped to Portuguese messages by error code (`invalid_credentials`, `email_not_confirmed`, `over_request_rate_limit`); other errors show a generic message.
- Local auth: `[auth] enable_signup = false` disables sign-ups while `[auth.email] enable_signup = true` keeps password logins; disabling the e-mail provider would also block logins.
- The development user in `seed.sql` is inserted into `auth.users` and `auth.identities` with a bcrypt hash; `supabase db reset` recreates it, and the v0.1 trigger gives it a profile and 16 default categories.

None. The v0.1 migrations are now applied to the hosted project (`supabase migration list` shows local and remote in sync).

## Security Changes

- Local: sign-ups disabled, minimum password length 8.
- Hosted: schema deployed with RLS; sign-ups must be disabled in the dashboard (pending confirmation).
- Cloudflare Pages: security headers and `robots.txt`.
- Post-login redirect restricted to same-origin paths.

## Tests

- pgTAP (`npm run test:db`): 5 files, 99 assertions, all passing after the config change and reseed.
- Local auth verified against GoTrue: password login succeeds for the development user, wrong password returns `invalid_credentials`, sign-up returns `signup_disabled`.
- `npm run build` and `npm run lint` pass.

## Bugs Found

- BUG-001: the first Cloudflare Pages build failed because `.node-version` contained `24`, which the build image resolved to Node 24.13.1; Angular CLI 22 requires 24.15.0 or newer.

## Bugs Fixed

- BUG-001: `.node-version` pinned to `24.18.0` (the version used locally) and `engines.node >= 24.15.0` declared in `package.json`.

## Known Limitations

- Password recovery and user invitations are handled by the administrator in the Supabase dashboard.
- The context selector and the dashboard keep mock data.
- Hosted auth settings (sign-up disabled, site URL, redirect URLs, minimum password length) are configured manually in the dashboard.

## Out of Scope

Public signup, invitations, password recovery in the application, profile editing, accounts and categories CRUD, transactions, households, grants.
