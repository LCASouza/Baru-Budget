# Baru Budget v0.2 — Auth, RLS and Deploy

## Status

IN_PROGRESS — architectural analysis delivered (`docs/ARCHITECTURE_ANALYSIS_V0.2.md`); implementation awaits approval.

## Objective

Make Baru Budget reachable from the internet, including mobile, with e-mail and password login, persistent session, protected routes and the v0.1 schema applied to the hosted Supabase project.

## Scope

- `AuthService`, `authGuard`, `guestGuard`, login page.
- `ProfileRepository` and `CurrentProfileService`; header shows the real profile; logout.
- Hosted Supabase: CLI link, `db push`, public signup disabled, redirect URLs.
- Cloudflare Pages project with automatic deploy from `main`; `_headers`, `robots.txt`.
- Local: signup disabled, development user in `seed.sql`.
- Unit tests for auth, guards, login and profile.

## Delivered

- `src/environments/environment.ts` filled with the hosted project URL and publishable key.

## Known Limitations

- Password recovery and user invitations are handled by the administrator in the Supabase dashboard.
- The context selector and the dashboard keep mock data.

## Out of Scope

Public signup, invitations, password recovery in the application, profile editing, accounts and categories CRUD, transactions, households, grants.

## Completion Criteria

- Migrations applied to the hosted project; `GET /rest/v1/profiles` with the publishable key returns an empty list.
- Public signup disabled in the hosted project.
- Login, logout and session restore after refresh work locally and in production.
- Unauthenticated access to any application route redirects to `/login`.
- Cloudflare Pages deploys `main` automatically; the public URL opens on a phone and the login works.
- `npm run build`, `npm test`, `npm run lint` and `npm run test:db` pass.
- `docs/versions/v0.2.md` and `docs/PROJECT_STATUS.md` updated; version marked DELIVERED only after all criteria are met.
