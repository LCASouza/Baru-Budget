## Technical Behavior

- Local stack: `npm run db:start` runs PostgreSQL 17, Auth, PostgREST, Studio and Mailpit in Docker (API `http://127.0.0.1:54321`, Studio `http://127.0.0.1:54323`). `npm run db:reset` reapplies all migrations and `supabase/seed.sql`.
- The Supabase client is created lazily by the injection token factory; the application starts even when the production environment has no Supabase values yet.
- The client uses the Supabase publishable key (`sb_publishable_...`). The local development key is fixed and public; it is versioned in `environment.development.ts`.
- Audit columns: `set_audit_on_insert` fills `created_by`/`updated_by` with `auth.uid()`, overriding client-supplied values when a user is authenticated; `set_audit_on_update` refreshes `updated_at`/`updated_by` and keeps `created_at`/`created_by` immutable. `profiles` only use `set_updated_at`.
- New users: the trigger `on_auth_user_created` on `auth.users` creates the profile (display name from metadata, then e-mail prefix, then `Usuário`) and seeds 16 default categories (7 income, 9 expense) owned by the user.
- Deviations from the architectural analysis: the `auth.users` trigger lives in its own migration (`20260905230600_auth_user_hooks.sql`) because it depends on `seed_default_categories`; audit helpers are two functions (`set_audit_on_insert`, `set_audit_on_update`) plus `set_updated_at`; the environment field is named `supabasePublishableKey`.
- `supabase/seed.sql` exists as an empty placeholder to satisfy the CLI seed configuration.
- Initial bundle budget raised to 1 MB warning / 1.5 MB error after adding supabase-js (initial raw size ~860 kB, ~197 kB transferred).

## Security Changes

- RLS enabled on `profiles`, `categories` and `accounts` in their creation migrations.
- Policies restricted to the `authenticated` role and to the owner (`(select auth.uid()) = owner_user_id`; `id` for profiles). No policy for `anon` or `public`.
- Clients cannot insert or delete profiles; creation happens through the auth trigger.
- `handle_new_user` and `seed_default_categories` are `security definer` with `search_path = ''`; execute privilege revoked from `public`, `anon` and `authenticated`.
- Ownership transfer is blocked by the `with check` clause of update policies; `created_by` cannot be spoofed or changed.
- No secret is versioned: the production environment is empty until v0.2 and only the public local key is committed.

## Known Limitations

- No authentication: the application cannot read protected data until v0.2; the UI keeps mock data.
- No screens for accounts and categories; CRUD is scheduled for v0.3.
- `environment.ts` (production) has empty Supabase values until the hosted project exists (v0.2).
- Applying migrations to a hosted project (`supabase link`, `supabase db push`) is part of v0.2.

## Out of Scope

Login, session, guards, transactions, households, grants, dashboard with real data, credit cards, installments, recurrences, allocations, settlements, loans, financings, Excel import/export, Cloudflare deployment.
