# Baru Budget v0.1 — Foundation

## Status

IN_PROGRESS — architectural analysis delivered (`docs/ARCHITECTURE_ANALYSIS_V0.1.md`); implementation awaits approval.

## Objective

Establish the technical foundation of Baru Budget: local Supabase project, migration strategy, base schema (profiles, categories, accounts), financial types, Supabase client, environments and initial tests, on top of the approved visual prototype.

## Scope

- Supabase CLI and local project (Docker).
- Migrations: helpers (`set_updated_at`), enums (`category_kind`, `account_type`, `transaction_kind`), `profiles`, `categories`, `accounts`.
- RLS enabled on every table with owner-only policies; no access for anonymous users.
- Profile creation trigger on `auth.users` with default category seeding.
- Generated database types, injectable Supabase client, environments (local development, production).
- pgTAP tests (schema, triggers, RLS, RLS enabled on all public tables) and Vitest tests for viewport, navigation, period filter, chart geometry and client provider.
- Cloudflare Pages preparation: `public/_redirects`, `.node-version`.
- Application version label in the sidebar.

## Known Limitations

- No authentication: the application cannot read protected data until v0.2; the UI keeps mock data.
- No screens for accounts and categories; CRUD is scheduled for v0.3.

## Out of Scope

Login, session, guards, transactions, households, grants, dashboard with real data, credit cards, installments, recurrences, allocations, settlements, loans, financings, Excel import/export, Cloudflare deployment.

## Completion Criteria

- `npx supabase db reset` applies all migrations without errors.
- `npx supabase test db` passes (schema, triggers, RLS).
- `ng build` and `ng test` pass.
- `database.types.ts` matches the migrations.
- Every table in `public` has RLS enabled and owner-only policies.
- No secret in the repository.
- `docs/versions/v0.1.md` and `docs/PROJECT_STATUS.md` updated; version marked DELIVERED only after all criteria are met.
